## 18. 중첩 컨테이너 저장 시 다른 컨테이너 영향 버그 수정

### 문제:
- 컨테이너 안에 컨테이너(ForEach, For, While 등)를 만들고 그 내부에서 작업한 내용이 다른 컨테이너에 영향을 줌
- 원인: `handleSave`에서 모든 노드의 `parentId`를 현재 컨테이너 ID로 일괄 덮어씀

### 문제 시나리오:
```
Container A (편집 중)
├── Node1 (parentId: undefined → A로 설정 ✓)
├── ForEach1 (parentId: undefined → A로 설정 ✓)
│   └── Child1 (parentId: ForEach1 → A로 덮어씀 ✗)
└── Container B
    └── Child2 (parentId: B → A로 덮어씀 ✗)
```

### 수정된 파일:
1. **src/components/ContainerFlowModal.tsx**

### 변경 내용:
기존 코드:
```typescript
const restoredNodes = latestNodes.map(n => ({
  ...n,
  parentId: containerId,  // 모든 노드에 적용
  extent: 'parent' as const,
  zIndex: 1000,
}));
```

수정 코드:
```typescript
const restoredNodes = latestNodes.map(n => {
  const isStartOrEnd = n.id.endsWith('-start') || n.id.endsWith('-end');
  const hasNestedParent = n.parentId && n.parentId !== containerId && !isStartOrEnd;

  return {
    ...n,
    parentId: hasNestedParent ? n.parentId : containerId,
    extent: 'parent' as const,
    zIndex: 1000,
  };
});
```

### 동작:
- 이미 `parentId`가 있는 노드(중첩 컨테이너의 자식)는 기존 `parentId` 유지
- `parentId`가 없거나 start/end 노드인 경우만 현재 컨테이너 ID 적용
- 중첩 컨테이너 구조가 저장 시에도 올바르게 유지됨

- ReactFlow는 `nodes` 배열의 **모든 노드**를 렌더링하기 때문에 중첩 자식도 표시됨

### 문제 시나리오:

For 컨테이너 FlowCanvas nodes 상태:
├── node1-start (parentId: undefined) → 표시 ✓
├── node1-end (parentId: undefined) → 표시 ✓
├── node2 (ForEach, parentId: undefined) → 표시 ✓
└── node3 (New Process, parentId: 'node2') → 표시됨 ✗ (숨겨야 함)
```

### 수정된 파일:
1. **src/components/ContainerFlowModal.tsx**

### 변경 내용:

   }, [nodes]);
   ```

- 다시 컨테이너를 열면 노드 연결선이 끊어져 있음

### 원인:

- `nestedEdges` 파라미터를 받지만 사용하지 않음

### 수정된 파일:
1. **src/components/ContainerFlowModal.tsx**

### 변경 내용:
`handleNestedContainerSave`에 엣지 저장 로직 추가:
```typescript
// 내부 엣지 저장
const childNodeIds = new Set(childNodes.map(n => n.id));
const startId = `${containerId}-start`;
const endId = `${containerId}-end`;

// 중첩 컨테이너 내부 엣지 (start/end 연결 포함)
const childEdges = nestedEdges.filter(e => {
  const sourceIsChild = childNodeIds.has(e.source) || e.source === startId || e.source === endId;
  const targetIsChild = childNodeIds.has(e.target) || e.target === startId || e.target === endId;
  return sourceIsChild && targetIsChild;
});

// 기존 중첩 컨테이너 엣지 제거 후 새 엣지 추가
setEdges(eds => {
  const otherEdges = eds.filter(e => {
    const sourceIsNested = childNodeIds.has(e.source) || e.source === startId || e.source === endId;
    const targetIsNested = childNodeIds.has(e.target) || e.target === startId || e.target === endId;
    return !(sourceIsNested || targetIsNested);
  });
  return [...otherEdges, ...childEdges];
});
```

## 21. 중첩 컨테이너 재오픈 시 노드/엣지 로드 안됨 버그 수정

### 문제:
- 컨테이너 내부에 컨테이너를 만들고 저장 후 다시 열면 내부 노드와 엣지가 없음
- 예: For → ForEach → 노드 추가 → 저장 → 재오픈 시 ForEach 내부 비어있음

### 원인:
- `getInitialNodes`가 **직접 자식만** 로드하고 **중첩 자식(손자 노드)**은 로드하지 않음
- For 컨테이너 로드 시 ForEach의 자식들(`parentId: 'ForEach'`)이 누락됨
- ForEach 재오픈 시 `nodes`에 자식이 없어서 빈 컨테이너로 표시

### 문제 흐름:
```
For 컨테이너 열기
└─ getInitialNodes('For', initialNodes)
└─ 로드됨: ForEach (parentId: 'For')
└─ 로드 안됨: NewProcess (parentId: 'ForEach') ❌

For 안에서 ForEach 열기
└─ getInitialNodes('ForEach', nodes)
└─ nodes에 NewProcess 없음 → 빈 컨테이너! ❌
```

### 수정된 파일:
1. **src/components/ContainerFlowModal.tsx**

### 변경 내용:

1. `getAllDescendantNodes` 헬퍼 함수 추가:
```typescript
const getAllDescendantNodes = (containerId: string, allNodes: Node[]): Node[] => {
  const descendants: Node[] = [];
  const visited = new Set<string>();
  const queue = [containerId];

  while (queue.length > 0) {
    const currentId = queue.shift()!;
    if (visited.has(currentId)) continue;
    visited.add(currentId);

    const children = allNodes.filter(n => n.parentId === currentId);
    descendants.push(...children);

    // 컨테이너 타입 자식은 큐에 추가하여 재귀 탐색
    children.forEach(child => {
      if (['for', 'forEach', 'while', 'group'].includes(child.type || '')) {
        queue.push(child.id);
      }
    });
  }
  return descendants;
};
```

2. `getInitialNodes` 수정 - 중첩 후손 포함:
```typescript
const allDescendants = getAllDescendantNodes(containerId, initialNodes);
const nestedDescendants = allDescendants.filter(n => n.parentId !== containerId);
return [startNode, endNode, ...processedNodes, ...nestedDescendants];
```

3. `getInitialEdges` 수정 - 중첩 엣지 포함:
```typescript
const allDescendants = getAllDescendantNodes(containerId, initialNodes);
// 직접 자식 엣지 + 중첩 컨테이너 내부 엣지 모두 포함
return initialEdges.filter(e => {
  return (sourceIsDirect && targetIsDirect) || (sourceIsDescendant && targetIsDescendant);
});
```

### 동작:
- 컨테이너 초기화 시 모든 후손 노드와 엣지를 로드
- 직접 자식: `parentId` 제거하여 현재 컨테이너에 표시
- 중첩 자식: `parentId` 유지하여 `visibleNodes`에서 숨김
- 중첩 컨테이너 재오픈 시 저장된 노드/엣지 정상 로드

## 22. App.tsx handleContainerFlowSave 중첩 엣지 저장 버그 수정

### 문제:
- 컨테이너 내부에 컨테이너를 만들고 노드를 연결한 후 저장
- 다시 컨테이너를 열면 중첩 컨테이너 내부의 노드 연결선이 끊어져 있음
- 예: For → ForEach → 노드 추가 및 연결 → 저장 → 재오픈 시 ForEach 내부 엣지 없음

### 원인:
1. **노드 중복 버그**: `nonInternalNodes` 필터가 `parentId !== containerId`를 확인
   - 손자 노드(`parentId = nestedContainerId`)가 남아있고
   - `newInternalNodes`에도 포함되어 중복 발생

2. **엣지 누락 버그**: `isOldInternal` 체크가 직접 자식만 확인
   - 중첩 컨테이너의 가상 start/end 노드(예: `forEachId-start`)는 `nodes` 배열에 없음
   - 손자 노드의 엣지가 "old internal"로 인식되지 않아 중복 또는 불일치 발생

### 수정된 파일:
1. **src/App.tsx**

### 변경 내용:

```typescript
// 기존 코드
setNodes((nds) => {
  const nonInternalNodes = nds.filter(n => n.parentId !== containerId);
  return [...nonInternalNodes, ...processedInternalNodes];
});

setEdges((eds) => {
  const nonInternalEdges = eds.filter(e => {
    const isOldInternal = nodes.some(n => n.parentId === containerId && (n.id === e.source || n.id === e.target));
    return !isOldInternal;
  });
  return [...nonInternalEdges, ...newInternalEdges];
});

// 수정 코드
// 새로운 내부 노드 ID 집합 (직접 자식 + 중첩 손자 모두 포함)
const newInternalNodeIds = new Set(newInternalNodes.map(n => n.id));

// 중첩 컨테이너들의 start/end 노드 ID도 추가
const allInternalNodeIds = new Set(newInternalNodeIds);
allInternalNodeIds.add(`${containerId}-start`);
allInternalNodeIds.add(`${containerId}-end`);
newInternalNodes.forEach(n => {
  if (['for', 'forEach', 'while', 'group'].includes(n.type || '')) {
    allInternalNodeIds.add(`${n.id}-start`);
    allInternalNodeIds.add(`${n.id}-end`);
  }
});

setNodes((nds) => {
  // ID 기반 필터링으로 중복 방지
  const nonInternalNodes = nds.filter(n => !newInternalNodeIds.has(n.id));
  return [...nonInternalNodes, ...processedInternalNodes];
});

setEdges((eds) => {
  // 모든 내부 노드(직접 자식 + 중첩 start/end + 손자) 관련 엣지 제거
  const nonInternalEdges = eds.filter(e => {
    const sourceIsInternal = allInternalNodeIds.has(e.source);
    const targetIsInternal = allInternalNodeIds.has(e.target);
    return !sourceIsInternal && !targetIsInternal;
  });
  return [...nonInternalEdges, ...newInternalEdges];
});
```

### 동작:
- `newInternalNodeIds`: 모달에서 받은 모든 내부 노드 ID (직접 자식 + 손자)

- 노드: ID 기반 필터링으로 기존 노드 제거 후 새 노드 추가 (중복 방지)
- 엣지: 내부 노드와 관련된 모든 엣지 제거 후 새 엣지 추가
- 중첩 컨테이너의 가상 start/end 노드 엣지도 정확히 처리됨
