## 3. 노드 연결 (Edge)

### TC-3.1 노드 연결 생성
| 항목 | 내용 |
|------|------|
| **사전조건** | 노드가 2개 이상 존재 |
| **테스트 단계** | 1. 노드 A의 하단 핸들(파란색 원) 드래그<br>2. 노드 B의 상단 핸들에 드롭 |
| **예상 결과** | A → B 연결선(엣지) 생성됨 |

### TC-3.2 엣지 삭제
| 항목 | 내용 |
|------|------|
| **사전조건** | 연결된 엣지 존재 |
| **테스트 단계** | 1. 엣지 클릭하여 선택<br>2. Delete 키 또는 Backspace 키 |
| **예상 결과** | 선택한 엣지 삭제됨 |

### TC-3.3 엣지 위에 노드 드롭 (자동 분할)
| 항목 | 내용 |
|------|------|
| **사전조건** | A → B 연결된 엣지 존재 |
| **테스트 단계** | 1. 새 노드 C 생성<br>2. 노드 C를 A → B 엣지 위로 드래그하여 드롭 |
| **예상 결과** | A → B 엣지 제거, A → C → B 엣지 자동 생성 |

### TC-3.4 분기 노드 연결 (IfElse)
| 항목 | 내용 |
|------|------|
| **사전조건** | IfElse 노드 존재 |
| **테스트 단계** | 1. IfElse 노드의 TRUE 핸들에서 드래그<br>2. 대상 노드에 연결<br>3. FALSE 핸들에서도 동일하게 연결 |
| **예상 결과** | TRUE/FALSE 두 개의 분기 연결 가능 |

### TC-3.5 Switch 노드 다중 연결
| 항목 | 내용 |
|------|------|
| **사전조건** | Switch 노드에 Case 2개 이상 추가 |
| **테스트 단계** | 1. 각 Case 핸들에서 별도 노드로 연결 |
| **예상 결과** | Case 수만큼 분기 연결 가능 |

## 4. 노드별 기능 테스트

### 4.1 Process 노드

**노드 설명**: 워크플로우의 기본 처리 단계를 나타내는 노드. 서비스 타입을 선택하여 다양한 처리 로직 설정 가능.

**UI 구성**:
- 헤더: 연파란색 배경, Workflow 아이콘, 노드 라벨, nodeId 표시
- 본문: 서비스 타입 드롭다운, 설정 버튼 (톱니바퀴 아이콘)
- 핸들: 상단 (입력), 하단 (출력)

#### TC-4.1.1 서비스 타입 드롭다운 열기
| 항목 | 내용 |
|------|------|
| **사전조건** | Process 노드가 캔버스에 존재 |
| **테스트 단계** | 1. Process 노드 본문의 "serviceType 선택" 드롭다운 버튼 클릭 |
| **예상 결과** | 드롭다운 메뉴가 열리며 서비스 타입 목록 표시:<br>- 기본 프로세스<br>- HTTP 서비스<br>- 데이터베이스<br>- 파일 처리<br>- 큐 처리<br>- 스케줄러 |

#### TC-4.1.2 서비스 타입 선택 및 입력 모달
| 항목 | 내용 |
|------|------|
| **사전조건** | 서비스 타입 드롭다운이 열린 상태 |
| **테스트 단계** | 1. "HTTP 서비스" 항목 클릭<br>2. ServiceTypeInputModal이 열림<br>3. 각 입력 필드 작성 (TEXT, PASSWORD, RADIO, CHECK, LIST 등)<br>4. "저장" 버튼 클릭 |
| **예상 결과** | 모달이 닫히고 노드에 "HTTP 서비스" 텍스트 표시 |

#### TC-4.1.3 서비스 설정 버튼
| 항목 | 내용 |
|------|------|
| **사전조건** | Process 노드에 서비스 타입이 이미 선택되어 있음 |
| **테스트 단계** | 1. 드롭다운 옆의 톱니바퀴(Settings) 아이콘 클릭 |
| **예상 결과** | ServiceTypeInputModal이 열리고, 이전에 입력한 값들이 채워진 상태로 표시 |

---

### 4.2 Variable 노드

**노드 설명**: 변수를 선언하고 저장하는 노드. 스크립트나 다른 노드에서 참조할 수 있는 변수명을 정의.

**UI 구성**:
- 헤더: 연두색 배경, 변수 아이콘, 노드 라벨, nodeId 표시
- 본문: "name" 라벨, 변수명 입력 필드, Save 버튼
- 저장 상태: 저장 완료 시 체크 아이콘으로 변경

#### TC-4.2.1 변수명 입력
| 항목 | 내용 |
|------|------|
| **사전조건** | Variable 노드가 캔버스에 존재 |
| **테스트 단계** | 1. 노드 본문의 텍스트 입력 필드 클릭<br>2. 변수명 입력 (예: "userCount")<br>3. 입력 필드 외부 클릭 또는 Enter |
| **예상 결과** | 입력한 변수명이 필드에 표시됨 |

#### TC-4.2.2 변수 저장
| 항목 | 내용 |
|------|------|
| **사전조건** | Variable 노드에 변수명이 입력된 상태 |
| **테스트 단계** | 1. "Save" 버튼 클릭 |
| **예상 결과** | Save 버튼이 체크 아이콘으로 변경되어 저장 완료 표시 |

#### TC-4.2.3 저장 후 수정
| 항목 | 내용 |
|------|------|
| **사전조건** | Variable 노드가 저장된 상태 (체크 아이콘 표시) |
| **테스트 단계** | 1. 변수명 입력 필드 클릭<br>2. 기존 값 수정<br>3. 입력 필드 외부 클릭 |
| **예상 결과** | 체크 아이콘이 다시 "Save" 버튼으로 변경 (미저장 상태) |

### 4.3 Mapping 노드

**노드 설명**: 노드 간 데이터 매핑을 정의하는 노드. 소스 필드와 타겟 필드를 연결하고 변환 함수 적용 가능.

**UI 구성**:
- 헤더: 연보라색 배경, 매핑 아이콘, 노드 라벨, nodeId 표시
- 본문: 매핑 개수 표시 (예: "3 mappings")
- 핸들: 상단 (입력), 하단 (출력)

#### TC-4.3.1 매핑 에디터 열기
| 항목 | 내용 |
|------|------|
| **사전조건** | Mapping 노드가 캔버스에 존재 |
| **테스트 단계** | 1. Mapping 노드 더블클릭 |
| **예상 결과** | MappingEditorModal이 전체 화면으로 열림.<br>좌측에 소스 노드 선택 영역, 우측에 타겟 노드 선택 영역 표시 |

#### TC-4.3.2 매핑 개수 표시 확인
| 항목 | 내용 |
|------|------|
| **사전조건** | Mapping 노드에 매핑이 설정된 상태 |
| **테스트 단계** | 1. Mapping 노드 본문 확인 |
| **예상 결과** | "N mappings" 형식으로 설정된 매핑 개수 표시 |

### 4.4 Script 노드

**노드 설명**: JavaScript/Java 스크립트를 작성하는 노드. 복잡한 로직이나 데이터 변환을 코드로 구현.

**UI 구성**:
- 헤더: 연보라색 배경, 코드 아이콘, 노드 라벨, nodeId 표시
- 본문:
  - "type:" 라벨 + 스크립트 타입 표시 (standard/function/expression)
  - "var:" 라벨 + 변수명 표시 (설정된 경우)

#### TC-4.4.1 스크립트 편집 모달 열기
| 항목 | 내용 |
|------|------|
| **사전조건** | Script 노드가 캔버스에 존재 |
| **테스트 단계** | 1. Script 노드 더블클릭 |
| **예상 결과** | ScriptEditModal이 열림. 좌측에 코드 에디터, 우측에 변수 등록 패널 표시 |

#### TC-4.4.2 스크립트 타입 선택
| 항목 | 내용 |
|------|------|
| **사전조건** | ScriptEditModal이 열린 상태 |
| **테스트 단계** | 1. 상단의 스크립트 타입 탭 확인 (standard, function, expression)<br>2. "function" 탭 클릭 |
| **예상 결과** | function 모드로 전환, 코드 에디터 영역 초기화 |

#### TC-4.4.3 코드 작성 및 자동완성
| 항목 | 내용 |
|------|------|
| **사전조건** | ScriptEditModal이 열린 상태 |
| **테스트 단계** | 1. 코드 에디터 영역 클릭<br>2. "Sys" 입력<br>3. 자동완성 목록 확인<br>4. "System.out.println" 선택 |
| **예상 결과** | 자동완성 드롭다운 표시, 선택한 코드가 에디터에 삽입됨 |

#### TC-4.4.4 변수 등록
| 항목 | 내용 |
|------|------|
| **사전조건** | ScriptEditModal이 열린 상태, 캔버스에 I/O 필드가 설정된 다른 노드 존재 |
| **테스트 단계** | 1. 우측 "변수 등록" 섹션의 "source (nodeI/O)" 드롭다운 클릭<br>2. 노드 선택 (예: "Process_1")<br>3. "fieldName" 드롭다운에서 필드 선택<br>4. "variableName" 입력 필드에 스크립트에서 사용할 변수명 입력 (예: "inputData")<br>5. "등록" 버튼 클릭 |
| **예상 결과** | 하단 "등록된 변수" 테이블에 새 행 추가됨 |

#### TC-4.4.5 스크립트 저장
| 항목 | 내용 |
